## 1. Summary

The documentation came first, as asked. All fifteen documents of the Canon were amended for the new direction (Amendment
A-1: security first, then AI, then quantum, with every other domain kept as modules) and for the new Stage 0 scope
(Amendment A-2: every processor and operating system the Canon names, with the print function `gen`, before the
self-hosting compiler begins). A new document, Tooling Dhar, covers the diagnostics, the editor server and the in-browser
playground. All seventeen documents (fifteen, plus the two amendments) are rebuilt as PDFs from Markdown sources in the
website's colours and type, so the Canon and the website look like one thing, and the website now lists them.

The compiler did not change in the second half of the period. In the first half Stage 0 gained the print function `gen`
and two silent errors were fixed. Nothing in the amended direction is built: no ARM64, RISC-V, WebAssembly or macOS back
end, no `std.crypto`, no playground. Stage 1 is still scaffolding and has not compiled itself.

## 3. What the Canon now says, in short

* **Direction (A-1).** Dhar is a language for trustworthy computation. Order of attack: cybersecurity, AI, quantum.
  Principles P1 to P6; design requirements R1 to R5 for the self-hosting compiler; gates S1 to S4, A1 to A4, Q1 to Q4. Web,
  backend, data, blockchain and Web3 and the other domains stay, as modules on the same core, and are never held back for
  lack of a gate. Nothing in the three tracks begins before Stage-beta compiles itself.
* **Targets (A-2).** One list (A-2 §3.1): Linux x86-64, Windows x64, macOS x86-64, macOS ARM64, Linux ARM64, Linux RISC-V 64
  and WebAssembly with WASI. Stage 0 emits directly, with no intermediate form. An unsupported target is a fatal error.
  Gate **G0** (the whole battery passes in an emulator) switches a target on; gate **G1** (it passes on the real system)
  is what counts. Stage-beta begins only when every committed target has passed G1; Stage-alpha is then frozen.
* **New documents and sections.** Tooling Dhar (diagnostics, the language server, `dhar test --vectors`,
  `dhar verify-build`, `dhar sbom`, and the in-browser playground in §5). Tempering Dhar §11 (the rule for claims).
  The Hallmark §7 (personal data under the Nigeria Data Protection Act 2023) and §8 (terms of the hosted services).
  Spec1 §4.7, §14.5, §14.6, §20.1, §20.2 (numeric types, secret values, arenas, `sys` across targets, `gen`).

## 6. Limits that matter

* **None of the amended direction is built.** Linux ARM64, Linux RISC-V 64, WebAssembly and both macOS targets do not exist
  and `dharc` refuses them. There is no `std.crypto`, no float or tensor type, no quantum back end, no playground. The
  Canon states a target; it is not a result.
* **Windows has run only in an emulator.** It is **Partly**. Under A-2 it has passed G0 and not G1.
* **Gate G1 needs real hardware** for four targets: an ARM64 Linux machine, a RISC-V 64 machine, a Windows x64 machine and
  an Apple computer of each kind. Stage-beta waits for all of them (A-2 §2). If one cannot be reached, A-2 §3 is revised to
  move that target to the candidate list; it is never counted as complete without its run (The Pact §3). This is the most
  likely cause of delay.
* **Apple silicon needs a code signature** on native programs, and Dhar has to produce it without an outside tool (A-1, P1).
  That is an open design question, recorded in The Pact §2.1.
* **Tooling Dhar is Proposed**, not Ratified. The Hallmark's §7 and §8 are a statement of intent and a map for counsel, not
  legal advice. **Counsel qualified in Nigerian law must review §7, §8 and the notice before the survey or any mailing list
  collects a contact detail.** The Hallmark says collection must not begin earlier.
* **The survey** was checked against an imitation of the database and its table rules on PostgreSQL (36 checks), not yet
  against the live project.
* **Spellings of the new keywords are provisional** (Spec1 marks each): `veil`, `unveil`, `blend`, `arena`, the wide and
  vector types, the `wrap_`, `sat_` and `chk_` arithmetic forms.
* **Spec0 §3, pillar 1** says "the parser is not written in assembly"; Stage-alpha's parser is. The sentence is the
  author's and was left as written.
* **The two Project PDFs** (`dhar Complete Picture.pdf` and `Architectural Blueprint Building a Fully Independent Systems
  Language.pdf`) are not part of the Canon and were not amended.
* **The PDFs are dark pages**, like the website, so they use a lot of ink if printed. A light variant is possible.
